# 📌 AnimeRecord - 自動化數據採集與動漫紀錄系統

這個專案是一個整合了 **Python 後端自動化爬蟲** 與 **Vue 3 前端數據驅動** 的獨立動漫紀錄 Web 應用。專案的核心在於透過自動化腳本定期採集巴哈姆特 ACG 的動漫資產，並在前端實現高流暢度的多維度資料篩選與本地筆記功能。

---

## 🛠️ 核心技術棧 (Tech Stack)

* **數據採集工程**：Python 3 (Requests, BeautifulSoup)
* **前端核心框架**：Vue 3 (Options API 實戰)
* **UI 視覺佈局**：Bootstrap 5 & 現代 CSS 動態漸層
* **數據永續方案**：LocalStorage 本地緩存 & JSON 數據序列化
* **建構工具**：Vue CLI (Webpack 5)

---

## 🚀 後端數據工程：自動化爬蟲與清洗機制

為了建立高達數百條的本地動漫資料庫（`gamerAcg-List.json`），我自主編寫了 Python 自動化採集腳本，並實作了以下邏輯：
1. **多頁面異步網路請求**：利用 `requests` 搭配自訂 `headers` 模擬瀏覽器行為，高效解析巴哈姆特 ACG 列表頁面的 HTML 結構。
2. **集合演算法數據去重 (Set Union)**：為了確保每次執行爬蟲時，新抓取的資料不會與既有資料重複，我將新舊資料序列化後轉為 Python 的 `Set` 集合，利用 **`oldDataSet.union(newDataSet)` 集合聯集運算** 達成自動化去重與無縫合併，確保資料庫的單一真實性。
3. **檔案格式標準化**：編寫腳本自動清洗下載的圖片副檔名（統一校正為小寫 `.png` / `.jpg`），避免因大小寫不一致導致網頁編碼讀取失敗。

## ⚡ 前端效能優化：延遲加載 (Lazy Loading)

* **痛點反思**：由於專案初期建構於 Vue CLI (Webpack) 環境下，當本地 JSON 資料庫日益龐大時，導致每次專案編譯、打包與部署（Deploy）的時間異常漫長，且使用者首次開啟網頁時會因載入過多資產而產生卡頓。
* **解決方案**：經由技術調研，我在此專案中導入了 **Lazy Loading（延遲加載）** 機制。透過路由與大型元件的代碼分割（Code Splitting），讓龐大的動漫資料與卡片元件僅在需要時才進行非同步載入。這不僅大幅縮減了初始 Bundle 的體積，讓網頁開啟達到秒開的流暢度，也顯著提升了開發時的打包編譯效率。

## 🎨 UI/UX 踩坑實錄與視覺工程化

### 1. 動態網格防擠壓設計 (Anti-Layout Shift)
* **踩坑**：原設計希望使用者點擊動漫卡片時，卡片能在網格內原地展開（Expandable Card）並顯示筆記欄位。然而實作後發現，卡片高度的動態延伸會劇烈擠壓下方排版，導致整體響應式網格（Grid）嚴重跑位。
* **解決方案**：策略性捨棄內嵌展開，改採 **Bootstrap 5 Modal（彈出式視窗）** 進行上下文隔離。這不僅為使用者開闢了獨立、專注的筆記寫作空間，更徹底杜絕了佈局位移（Layout Shift）對網頁視覺造成的破壞。

### 2. 異質圖片標準化裁剪系統 (Object-Fit Alignment)
* **挑戰**：透過 Python 爬蟲採集的封面圖源自不同載點，原始尺寸與長寬比例參差不齊，直接渲染會造成卡片高度不一、或產生不美觀的白邊。
* **解決方案**：運用 CSS 現代化佈局技術，為圖片外層容器設定固定的寬高比例，並搭配 **`object-fit: cover`** 與置中定位（`object-position: center`）。確保所有不規則比例的圖片皆能在無邊框、不失真的前提下完美填滿卡片，達成視覺的整齊與精緻度。
